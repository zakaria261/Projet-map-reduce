02 / 09
Contexte

Qu'est-ce que MapReduce ?

  • 🏭
    Paradigme de calcul distribué inventé par Google (2004) — base de Hadoop, Spark et consorts.
  • 📂
    Idée principale : diviser un gros problème en tâches indépendantes (Map), les traiter en parallèle, puis agréger les résultats (Reduce).
  • 🎯
    Notre cas d'usage : compter la fréquence de chaque mot dans plusieurs fichiers texte, en parallèle sur plusieurs machines.
  • 🔧
    Notre contrainte : Python pur, stdlib uniquement — aucun framework distribué, tout fait à la main.

Architecture

4 phases, 3 composants

1 worker par fichier

Ouvre un socket TCP
02

Routage par hash MD5
Chaque mot → 1 seul reducer
03
REDUCE
Agrège tous les MAP
Somme les occurrences
Sauvegarde en JSON
04
MERGE
Coordinateur fusionne
Trie par fréquence
Affiche le Top-N
🔵
MAP Worker
map_worker.py — 1 par fichier, ouvre un port TCP (6000+id), attend que les reducers viennent chercher les données.
🟢
REDUCE Worker
reduce_worker.py — contacte tous les MAP, agrège les mots de sa partition, écrit result_reducer_N.json.
🟡
Coordinateur
coordinator.py — orchestre le lancement, attend les résultats, fusionne et affiche. Supporte local et Docker.
04 / 09
Phase 1

MAP — Lire et compter

  • 📄
    Un fichier par worker — le coordinateur assigne un fichier à chaque MAP worker au démarrage.
  • 🔡
    Tokenisation regex — [a-zA-ZÀ-ÿ]+ — supporte les accents français (é, è, ê, ô…)
  • 🚫
    Filtrage — 50+ stopwords (le, de, the, and…) et mots < 3 caractères ignorés.
  • 🔌
    Serveur TCP — ouvre un socket sur le port 6000 + son ID et attend les connexions des reducers.
# Extraction des mots (avec accents) words = re.findall([a-zA-ZÀ-ÿ]+, text.lower()) # Filtrage stopwords + longueur for w in words: if w not in STOPWORDS and len(w) > 2: counts[w] = counts.get(w, 0) + 1
05 / 09
Phase 2 & 3

SHUFFLE + REDUCE — Regrouper et agréger

  • ↕️
    Pull TCP — chaque reducer se connecte à chaque MAP worker et demande ses mots via un message JSON.
  • 🔒
    Partitionnement MD5 — hash(mot) % N_reducers. On utilise MD5 car hash() Python change à chaque exécution (PYTHONHASHSEED). MD5 est toujours identique.
  • 🔄
    Backoff exponentiel — 20 tentatives × 1s si un MAP n'est pas encore prêt. Robustesse réseau.
  • 💾
    Résultat partiel — chaque reducer écrit son propre fichier result_reducer_N.json avec ses mots triés.
# Partitionnement déterministe def get_reducer_for_word(word, N): h = int(hashlib.md5( word.encode() ).hexdigest(), 16) return h % N # Protocole TCP — préfixe de longueur def send_data(sock, data): payload = json.dumps(data).encode() length = struct.pack('>I', len(payload)) sock.sendall(length + payload)
06 / 09
Détail technique

Protocole TCP length-prefix

  • ⚠️
    Le problème : TCP est un flux d'octets continu. Un gros JSON peut arriver en plusieurs morceaux — ou deux messages collés ensemble.
  • ✅
    La solution : chaque message est précédé de 4 octets big-endian indiquant sa taille. Le receveur lit exactement ce nombre d'octets.
  • 📡
    Format : [ 4 octets taille ][ payload JSON UTF-8 ]
  • ⏱️
    Timeout 15s par connexion MAP pour éviter les blocages infinis en cas de nœud mort.
Flux réseau :
│ 0x00 0x00 0x00 0x48 │ ← taille (72 octets)
│ {"bonjour":5, ...} │ ← payload JSON
│ 0x00 0x00 0x01 0xF4 │ ← taille msg suivant
│ {"monde":12, ...} │ ← payload suivant
Résultat
Aucune troncature, aucun chevauchement de messages possible — même sous forte charge réseau.
07 / 09
Déploiement

3 modes, une seule codebase

Local
Machine unique
Le coordinateur lance les workers comme sous-processus. Aucune config requise.
python coordinator.py
--reducers 4 --top 20
Docker
Cluster simulé
6 conteneurs sur bridge Docker. MAP workers dans des conteneurs séparés. Volume partagé pour l'output.
docker-compose up --build
# 3 MAP + 2 REDUCE + coord
LAN réel
Multi-machines
Chaque machine du groupe lance un MAP. Les IPs sont configurées dans une variable d'environnement.
# fichier .env
MAP_HOSTS=192.168.1.42:6000,
         192.168.1.43:6001
Résolution d'adresse (priorité décroissante) :    ① MAP_HOSTS (IPs LAN explicites)  →  ② MAP_HOST_PREFIX (noms Docker : map-0, map-1…)  →  ③ Localhost (mode local par défaut)
